# WeTest Framework Blueprint — Claude Code Instructions

## Project overview

Playwright + TypeScript test automation framework for the **Toolshop** application (`practicesoftwaretesting.com`). Used as a conference blueprint (WeTest 2026). Two test layers: UI (Page Object Model) and API (typed helpers + Zod schema validation).

**Application under test**

| Layer | Local | Remote (acc) |
|---|---|---|
| Frontend (Angular) | `http://localhost:4200` | `https://practicesoftwaretesting.com` |
| API (Laravel) | `http://localhost:8091` | `https://api.practicesoftwaretesting.com` |
| Swagger | `http://localhost:8091/api/documentation` | — |

**Default accounts**

| Role | Email | Password |
|---|---|---|
| Admin | `admin@practicesoftwaretesting.com` | `welcome01` |
| Customer | `customer@practicesoftwaretesting.com` | `welcome01` |

## Architecture

```

  api/          # API specs — one file per resource, no baseURL override

support/

  utils/
    fixtures/testFixture.ts       # Custom Playwright fixture — source of truth for test imports
```

## Environment variable system

Global setup (`support/globalSetup.ts`) loads `support/environment/.env.global` then `support/environment/.env.${ENV}` (default: `tst`) before any tests run.

**URL variables**

| Variable | tst | acc |
|---|---|---|
| `BASE_URL` | `http://localhost:4200` | `https://practicesoftwaretesting.com` |
| `API_BASE_URL` | `http://localhost:8091` | `https://api.practicesoftwaretesting.com` |

**Endpoint variables** (used by API helpers — never hardcode paths)

```
BRANDS_ENDPOINT=/brands
# add others as: {RESOURCE}_ENDPOINT=/path
```

When adding a new API helper, register its endpoint in both `.env.tst` and `.env.acc` first.

## API testing layer

### ApiResult<T> — the return type of every helper method

```ts
// support/utils/helpers/apiHelpers/apiTypes.ts
export interface ApiResult<T> {
  status: number;
  body: T;
}
```

### Helper pattern (`brandsApiHelper.ts` is the reference)

```ts
import { APIRequestContext, APIResponse } from '@playwright/test';
import { ApiResult } from './apiTypes';
import { BrandResponse as Brand } from '../../../.zod/schemas/brandResponse';

async function resolve<T>(call: Promise<APIResponse>): Promise<ApiResult<T>> {
    const res = await call;
    return { status: res.status(), body: await res.json().catch(() => null) };
}

export abstract class BrandsApiHelper {
    static getAll(request: APIRequestContext): Promise<ApiResult<Brand[]>> {
        return resolve(request.get(process.env.API_BASE_URL! + process.env.BRANDS_ENDPOINT));
    }
    // ... one static method per endpoint
}
```

Rules:
- `abstract class` with `static` methods — never instantiate
- All URLs: `process.env.API_BASE_URL! + process.env.{RESOURCE}_ENDPOINT`
- Auth-protected methods accept `token: string` and set `Authorization: Bearer ${token}`
- Return body type comes from Zod-generated schemas in `support/.zod/schemas/`

### Spec pattern (`brands.spec.ts` is the reference)

```ts
import { expect, test } from "@playwright/test";
import { HttpStatus } from "../../support/enums/httpStatus";
import { BrandsApiHelper } from "../../support/utils/helpers/apiHelpers/brandsApiHelper";
import { getBrandsResponse } from "../../support/.zod/brand";

test.describe("Brands API", () => {
    test("returns an array of brands", async ({ request }) => {
        const { body: brandsResponse } = await test.step("Fetch all brands", async () => {
            const result = await BrandsApiHelper.getAll(request);
            expect(result.status).toBe(HttpStatus.OK);
            return result;
        });

        await test.step("Validate brands response", async () => {
            const validationResult = getBrandsResponse.safeParse(brandsResponse);
            expect(validationResult.success, validationResult.error?.message).toBe(true);
        });
    });
});
```

Rules:
- No `test.use({ baseURL })` — helpers handle the full URL
- Each test: one **act step** (calls helper, asserts status, returns result) + one **validate step** (Zod safeParse)
- Error case tests (4xx) only need the act step — no Zod validation
- Import Zod validators from `support/.zod/{resource}.ts` (grouped file), not individual schema files

## UI testing layer

### Test imports

Always import `test` from the custom fixture, not directly from `@playwright/test`:

```ts
import { test } from '../../support/utils/fixtures/testFixture';
```

This gives access to: `page`, `assertionHelper`, `sharedComponents`, `homePage`, `loginPage`, `chatPage`, `logger`.

### Page Object Model pattern (`login.page.ts` is the reference)

```ts
export class LoginPage extends BasePage {
    readonly usernameInput: Locator;

    constructor(page: Page, language?: string) {
        super(page, language);
        const t = this.t.loginPage;
        this.usernameInput = this.page.getByRole('textbox', { name: t.usernameInput });
    }

    async enterLoginCredentials(username: string, password: string) {
        await this.usernameInput.fill(username);
        await this.passwordInput.fill(password);
        await this.loginButton.click();
    }
}
```

Rules:
- Locator priority: `getByRole` > `getByTestId` (attr: `data-test`) > `getByLabel` > `getByText`
- No assertions inside page objects
- Wire new POMs into `testFixture.ts` (`CombinedFixtures` type + `baseTest.extend`)

## Design patterns

Four patterns are used in this framework. Apply them as described below — do not introduce them outside of their designated contexts.

---

### Builder — constructing complex request bodies

**Where:** `support/utils/builders/{resource}Builder.ts`
**When:** an API test needs to create a request body with more than two fields, or where optional fields need to vary between tests.

```ts
// support/utils/builders/productBuilder.ts
export class ProductBuilder {
    private data = {
        name: 'Default Product',
        price: 9.99,
        category_id: '01',
        brand_id: '01',
        description: '',
        stock: 10,
    };

    withName(name: string)             { this.data.name = name;              return this; }
    withPrice(price: number)           { this.data.price = price;            return this; }
    withStock(stock: number)           { this.data.stock = stock;            return this; }
    withCategory(categoryId: string)   { this.data.category_id = categoryId; return this; }

    build() { return { ...this.data }; }
}

// Usage in a test:
const payload = new ProductBuilder().withName('Hammer').withStock(0).build();
const result  = await ProductsApiHelper.create(request, token, payload);
```

---

### Factory — creating test data and page objects

**Where:** `support/utils/factories/{resource}Factory.ts`
**When:** tests need pre-configured objects (data payloads or page instances) without repeating setup logic.

```ts
// support/utils/factories/userFactory.ts
export class UserFactory {
    static customer() {
        return { email: 'customer@practicesoftwaretesting.com', password: 'welcome01' };
    }
    static admin() {
        return { email: 'admin@practicesoftwaretesting.com', password: 'welcome01' };
    }
    static guest(overrides: Partial<{ email: string; password: string }> = {}) {
        return { email: 'guest@example.com', password: 'Test1234!', ...overrides };
    }
}

// Usage in a test:
const { email, password } = UserFactory.customer();
await loginPage.enterLoginCredentials(email, password);
```

---

### Strategy — swappable authentication behaviour

**Where:** `support/utils/strategies/authStrategy.ts`
**When:** a test or helper needs to authenticate differently depending on role, and that choice should be decoupled from the test body.

```ts
// support/utils/strategies/authStrategy.ts
export interface AuthStrategy {
    getToken(request: APIRequestContext): Promise<string>;
}

export class CustomerAuthStrategy implements AuthStrategy {
    async getToken(request: APIRequestContext) {
        const result = await UserApiHelper.login(request, UserFactory.customer());
        return result.body.access_token;
    }
}

export class AdminAuthStrategy implements AuthStrategy {
    async getToken(request: APIRequestContext) {
        const result = await UserApiHelper.login(request, UserFactory.admin());
        return result.body.access_token;
    }
}

// Usage in a test:
const strategy: AuthStrategy = new AdminAuthStrategy();
const token = await strategy.getToken(request);
const result = await ProductsApiHelper.create(request, token, payload);
```

---

### Facade — single entry point hiding framework complexity

**Where:** already implemented — `support/utils/fixtures/testFixture.ts` is the UI facade; API helpers are the API facade.
**When:** adding a new helper that combines multiple lower-level operations into one call.

`testFixture.ts` exposes `page`, `loginPage`, `homePage`, `assertionHelper` etc. as a single import — callers never construct these individually.

For API tests, each helper class is a facade over `APIRequestContext`: callers pass `request` and get an `ApiResult<T>` back without knowing about headers, base URLs, or JSON parsing.

```ts
// Adding a new facade method — combine two steps behind one call:
// support/utils/helpers/apiHelpers/cartApiHelper.ts
static async addAndVerify(
    request: APIRequestContext,
    token: string,
    productId: string
): Promise<ApiResult<CartResponse>> {
    const result = await CartApiHelper.addItem(request, token, productId);
    if (result.status !== HttpStatus.CREATED) {
        throw new Error(`Cart add failed: ${result.status}`);
    }
    return CartApiHelper.get(request, token);
}
```

## Critical rules

**Always**
- Run `npx tsc --noEmit` after any TypeScript changes
- Use `HttpStatus.OK` not `200`, `Durations.FIVE_SECONDS` not `5000`
- Use `POLLING_CONFIG` presets instead of inline `waitFor` timeouts
- Register new endpoint env vars in both `.env.tst` and `.env.acc`
- Never edit files under `support/.zod/` — they are auto-generated by orval

**Never**
- Hardcode URLs or endpoint paths in helpers or tests
- Use `test.use({ baseURL })` in API specs
- Put assertions inside page object methods
- Use magic HTTP status numbers in assertions
- Call `new BrandsApiHelper()` — all methods are static
